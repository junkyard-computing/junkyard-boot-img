# Lab units — NEVER flash these in a fleet sweep.
#
#   ./flash-nmap.sh -X fleet/lab-units.txt --flash <targets>
#
# These three felixes are the development rig and are PERMANENTLY lab units. The
# image they build is destined for data-center units, which are different
# hardware instances entirely.
#
# Why an exclusion list and not the fleet stamp: the lab units deliberately carry
# a BLANK /etc/junkyard-fleet, so a sweep that passes `--fleet <dc-name>` already
# skips them. But that protection only exists when someone remembers the flag. A
# default sweep matches them, and correctly so — they pass every ownership test
# the script has: they authorize the fleet deploy key, grant it root, run our
# overlay, and report a version we built. Nothing about "ours" distinguishes the
# machine you develop on from the machine you ship to.
#
# The cost of getting this wrong is asymmetric. The boot chain is A/B-safe, but
# the rootfs half overwrites `super` in place with no rollback — so a stray sweep
# does not inconvenience the rig, it re-images it, and whatever experiment was
# mid-flight is gone. Serials are the right key here (not addresses): DHCP leases
# follow the dongle MAC and move between units.
#
# Exclusions are also the half of the gate that stays knowable. The inclusion
# side scales by itself (key + markers + --from-version); this list stays short
# and is maintained by hand, which is only sustainable because it is short.
#
# One serial per line. Blank lines and # comments are ignored.
